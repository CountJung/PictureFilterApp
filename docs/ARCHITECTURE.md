# 설계 초안

현재 SwiftUI 편집 화면, 시스템 카메라 입력, Core Image 정지 이미지 필터와 Vision 인물 효과를 구현했습니다. 다음 목표는 밝고 화사한 인물 필터와 지원 배율을 조절하는 전용 촬영 흐름입니다. 아래 기존 구현 설명과 마지막의 후속 설계를 구분합니다.

| 영역 | 책임 |
| --- | --- |
| App | 앱 시작과 서비스 연결 |
| Features/Editor | 사진 선택·촬영, 필터·인물 보정 상태, 초기화, 저장 요청 |
| Services | 사진 읽기와 결과 저장, 권한 처리 |
| Rendering | 원본과 편집 설정을 입력받아 미리보기·출력 렌더링 |
| Models | 이미지 정보, 필터 설정, 처리 상태와 오류 |
| Resources | 배포 가능한 샘플 이미지와 UI 리소스 |

## 데이터 흐름

선택·촬영 또는 샘플 → 원본 보관 → 편집 설정(색상 필터·피부 보정·인물 조명·배경 흐림) → 미리보기 렌더링 → 동일 설정으로 출력 렌더링 → 저장 결과 안내.

원본을 매번 기준으로 계산하여 필터가 누적되지 않게 합니다. 빠른 슬라이더 변경은 마지막 요청 결과만 화면에 반영합니다. 미리보기 크기와 출력 크기를 분리하고, 비동기 처리 중 사진 변경으로 오래된 결과가 덮어쓰지 않도록 설계합니다.

## 폰 없는 개발을 위한 분리

사진 입력과 저장은 인터페이스 뒤로 분리하고 샘플 입력, 메모리/임시 파일 저장, 권한 거부와 저장 실패 대역을 둡니다. UI는 실제 사진 서비스와 대역을 같은 방식으로 호출하도록 계획합니다. 대역의 성공은 OS 사진 보관함이나 실기기 권한 검증의 성공이 아닙니다.

## 카메라 및 얼굴 보정 · PF-021

카메라 입력은 UIKit 시스템 카메라 피커를 통해 편집 모델의 공통 이미지 입력 경로로 연결합니다. 카메라가 없는 시뮬레이터는 미지원 안내를 표시합니다. 피부 보정은 Vision 얼굴 랜드마크를 좌우 순으로 정렬해 인물별 마스크를 만들고, Core Image에서 원본 위에 선택적으로 혼합합니다. 눈·눈썹·입을 제외하고 얼굴 외곽으로 마스크를 제한하며, 사용자가 인물별 강도를 바꾸거나 해당 인물을 원상태로 돌릴 수 있습니다. 얼굴이 검출되지 않거나 Vision 요청이 실패하면 원본 픽셀을 보존합니다. 사진은 기기 안에서 처리하며 실시간 카메라 미리보기 보정은 범위 밖입니다.

## 인물 조명과 배경 깊이 효과 · PF-025

`PortraitEffects`는 Vision 얼굴 윤곽을 좌우 순으로 정렬해 선택 대상의 얼굴 안쪽에 약한 노출 보정을 혼합합니다. 배경 흐림은 사진에 저장된 깊이 정보를 요구하지 않고 `VNGeneratePersonInstanceMaskRequest`로 사람 인스턴스를 분리해 전경을 보존하고 배경에 Core Image Gaussian blur를 적용합니다. 모든 강도는 기본 0이며, 원본 비교와 전체 초기화가 유지됩니다. 얼굴 검출 또는 사람 마스크 생성에 실패하면 해당 효과는 입력 이미지를 그대로 반환합니다. 미리보기와 내보내기는 같은 설정과 온디바이스 렌더링 경로를 공유합니다.

저장 해상도, 색 공간, 메타데이터, 입력 형식, 최소 iOS 버전은 [DECISIONS](DECISIONS.md)의 PF-003을 따릅니다. 개인 사진과 위치 정보를 로그나 저장소에 포함하지 않습니다.

## PF-005 구현 구성

- `ImageInputService`: 비동기 이미지 Data 입력 계약. `BundleSampleInput`은 등록된 번들 PNG를 읽고 디코딩 가능 여부를 검사합니다.
- `ImageOutputService`: 비동기 저장 후 결과 UUID 반환 계약. 현재 `MemoryImageOutput`은 actor 내부에서 Data를 보관합니다. 사진 보관함에는 쓰지 않습니다.
- `AppServices`: 앱에서 SwiftUI 환경으로 주입합니다. 후속 화면은 `imageServices`를 통해 같은 계약을 사용합니다.
- `FailingImageInput` 및 `MemoryImageOutput(failure:)`: 입력 실패, 권한 거부, 저장 실패를 재현합니다. 저장 실패 시 결과가 남지 않습니다.
- 메모리 저장은 현재 세션용입니다. UUID로 결과를 조회하고 `removeAll()`로 비울 수 있으며, 영속 저장이나 출력 JPEG 변환은 PF-011 범위입니다.

샘플은 직접 생성한 640×480 및 480×640 PNG 색상표입니다. 상단 원색 구간, 가로·세로 그라데이션, 방향 구분용 검은 테두리가 있습니다. 외부 사진·개인 정보가 없으며 이 프로젝트에서 수정·배포할 수 있습니다. 자연 사진 품질이나 EXIF 회전 검증용 샘플은 아닙니다.

PF-005는 서비스 구성 및 주입까지이며 샘플 선택·표시는 PF-006의 EditorView에서 연결합니다.

## PF-006 화면 구성

WelcomeView에서 가로/세로 샘플을 선택하면 EditorView로 이동합니다. EditorView는 주입된 입력 서비스를 사용해 사진을 읽고 scaledToFit으로 방향·비율을 유지합니다. 사진 변경 메뉴와 이전 화면 복귀를 제공합니다.

로딩 표시, 입력 오류 안내와 재시도도 포함합니다. 요청 교체 시 이전 task의 결과가 화면을 덮어쓰지 않도록 취소 상태를 검사합니다. PF-006 당시 필터 목록은 표시만 했으며 PF-008에서 필터·강도 조작을 연결했습니다. 저장은 후속 작업입니다. 모델 기반 편집 상태는 PF-007에서 연결했으며, 실제 필터는 PF-008에서 연결했으며 시스템 사진 선택은 PF-010에서 구현합니다.

## PF-007 편집 상태 모델

`EditorModel`은 MainActor에서 관찰 가능한 상태를 관리하며 View는 상태를 표시하고 입력 로드를 요청합니다.

- `originalData`와 `originalImage`: 읽기 전용 원본. 필터 선택·강도 조절·초기화로 변경하지 않음.
- `EditSettings`: 필터와 강도. 기본 원본/0.5, 강도는 0~1로 제한하고 NaN·무한대는 무시.
- `Phase`: idle → loading → ready 또는 failed. 취소 시 idle, 실패 후 재시도 가능.
- 사진 변경: 이전 이미지·오류·설정을 비운 후 새 이미지 로드.
- 초기화: ready 상태에서 원본 유지, 설정만 기본값 복원.
- 입력 요청 ID: 이전 요청의 성공·실패가 새 사진 상태를 덮어쓰지 않도록 검사.

초기화 버튼은 모델에 연결했습니다. 필터 선택·강도 API는 모델 테스트로 검증했으며 화면 조작은 PF-008에서 활성화했습니다. 렌더링 요청 순서 및 성능 처리는 PF-009 범위입니다.

## PF-008 필터 미리보기

FilterRenderer actor가 ImageIO 축소·방향 보정 → Core Image 효과 → 강도 혼합 → sRGB PNG 미리보기를 수행합니다. CIContext는 재사용하며 항상 originalData와 현재 설정으로 새 결과를 계산합니다.

EditorModel은 previewImage를 원본과 별도로 보관하고 previewRevision으로 설정/사진 변경을 식별합니다. View의 task가 최신 미리보기를 요청하며 이전 결과는 revision 검사로 배제합니다. PF-009부터 설정 변경 시 직전 미리보기를 유지하고 처리 표시를 띄우며, 사진 교체 시에는 지웁니다. 실제 기기 부하 검증은 PF-019에 남아 있습니다.

필터 버튼·강도 슬라이더·초기화가 연결되었고 원본 필터에서는 강도 조절이 비활성입니다. 비교 영역을 누르는 동안 원본을 표시하되 설정은 유지합니다. 저장은 PF-011 전까지 비활성입니다. 실패 시 미리보기 오류와 재시도를 제공합니다.

## PF-009 연속 요청과 취소

- View의 revision 기반 task 수명을 그대로 사용하며 120ms 조용한 구간 뒤 렌더링합니다. 연속 입력은 이전 task 취소와 revision 검사로 병합합니다.
- 동일 필터·동일 강도와 무효 숫자는 revision을 갱신하지 않습니다.
- 각 실행은 별도 render ID를 가집니다. 설정 revision과 실행 ID가 모두 맞는 결과만 이미지·오류·진행 표시를 갱신합니다.
- 설정 변경 중에는 직전 결과를 유지하여 원본으로 깜빡이는 현상을 줄입니다. 새 사진 로드 시에는 이전 결과를 비웁니다.
- 취소는 사용자 오류로 표시하지 않습니다. 재시도는 별도 unstructured task 대신 revision 갱신으로 View task에 연결합니다.
- FilterRenderer는 축소 전후·Core Image 렌더 전후·PNG 인코딩 후 취소를 확인합니다. 이미 실행 중인 시스템 픽셀 연산 자체를 강제 중단하지는 못하지만, 이후 단계와 결과 반영을 차단합니다.

PreviewRendering과 대기 함수를 주입할 수 있어 테스트에서 응답 순서를 직접 제어합니다. 실제 폰 처리 시간·메모리·발열 측정 완료를 의미하지 않습니다.

## PF-010 시스템 사진 입력

`EditorView`는 `PhotosPicker`를 통해 시스템 사진 보관함에서 이미지 한 장을 선택합니다. 선택 버튼은 화면 본문에 배치해 시뮬레이터와 UI 자동화에서 모두 접근할 수 있게 했습니다. 시스템 picker가 취소되면 선택 항목이 바뀌지 않으므로 현재 편집 상태를 유지합니다.

`PhotosPickerItem`의 `Data`를 받은 뒤 `EditorModel.load(_:title:)`에 주입합니다. 모델은 번들 샘플 입력과 같은 `originalData`·`originalImage`·`Phase` 상태를 사용하므로 필터 미리보기는 입력 출처와 관계없이 동일하게 동작합니다. 데이터가 없거나 디코딩에 실패하면 기존 오류 상태로 전환하고 재시도 가능한 상태를 유지합니다.

원본 `UIImage`의 방향 메타데이터는 보관하며, 필터 렌더링은 ImageIO의 변환 옵션으로 방향을 적용한 축소 이미지를 만듭니다. 시뮬레이터에서 시스템 사진 보관함에 사진이 없을 때의 실제 선택 결과와 실기기 권한·iCloud 동작은 후속 검증으로 남습니다.

## PF-011 이미지 출력과 저장

`OutputRendering`은 원본 데이터와 저장 시점의 편집 설정을 받아 출력 이미지를 만듭니다. `FilterRenderer.renderOutput`은 ImageIO로 방향을 적용하고 긴 변 4096px 이하로 축소한 뒤 동일한 Core Image 필터·강도 계산을 사용합니다. 출력은 sRGB JPEG 품질 0.9이며 투명 영역은 흰색에 합성합니다. EXIF·GPS 등 메타데이터는 복사하지 않습니다.

`JPEGImageDocument`를 시스템 파일 내보내기에 전달해 JPEG를 저장합니다. 파일 가져오기는 JPEG·PNG·HEIC 한 장을 읽어 같은 편집 모델에 넣습니다. 사진 보관함 저장은 `PhotoLibraryImageOutput`이 add-only 권한을 요청한 뒤 임시 JPEG 파일을 새 자산으로 등록하고, 완료 후 임시 파일을 제거합니다. 앱은 저장 중 진행 상태와 결과 메시지를 보여줍니다. 메모리 대역은 UI 테스트 및 단위 테스트에서 저장 동작을 분리해 검증합니다.

시뮬레이터에서 `photos-add` 권한을 부여한 뒤 사진 저장 완료 콜백을 UI 테스트로 확인했습니다. 권한 거부·중복 저장 방지와 권한 안내 구현은 PF-012에 기록합니다. 실제 iOS 설정 앱에서 권한을 다시 허용하는 OS 복구 흐름은 수동 확인 대상입니다. 파일 내보내기·가져오기는 화면 진입과 제어 노출을 시뮬레이터에서 확인했으며, 저장 위치 선택과 파일을 다시 고르는 세부 상호작용은 파일 선택 UI가 제공하는 흐름을 따릅니다.

## PF-012 오류·권한·중복 동작 처리

사진 보관함 저장의 `.denied`·`.restricted` 결과는 `permissionDenied`로 바꾸고 앱은 설정에서 접근을 허용하라는 안내와 설정 열기 버튼을 표시합니다. 일반 렌더링·저장 실패는 실패 문구와 다시 저장 버튼을 제공합니다. 파일·사진 저장 취소는 오류 메시지로 처리하지 않습니다.

사진 저장 중에는 진행 표시를 보여주고 사진 변경, 입력 선택, 필터 조작, 초기화, 가져오기 및 추가 저장 메뉴를 비활성화합니다. 저장 메서드는 MainActor에서 `isSaving`을 첫 await 전에 설정해 반복 탭이 별도 요청을 만들지 못하게 합니다. 시스템 파일 내보내기 창이 열린 동안에도 같은 잠금을 유지하고 완료·취소 콜백에서 해제합니다.

`PictureFilterApp`은 UI 테스트 전용 실행 인자로 권한 거부, 저장 실패, 지연 저장 대역을 선택합니다. 기본 앱 실행은 실제 Photos 서비스를 사용합니다. 시뮬레이터 UI 테스트는 거부 안내·설정 버튼, 재시도, 지연 중 잠금 상태를 확인합니다. 실제 iOS 설정 앱으로 이동해 권한을 다시 허용하는 복구 절차는 앱 밖의 OS 동작이라 자동화 범위에 포함하지 않습니다.

## 후속 설계 · 화사한 인물 필터와 전용 카메라

다음은 예정 설계이며 구현 완료 상태는 TASKS에서 관리합니다.

- **인물 편집:** 선택 중인 얼굴 ID는 UI 편집 대상으로만 사용합니다. 렌더러는 원본 분석에서 얻은 같은 얼굴 ID와 모든 인물의 최종 설정을 사용합니다. 개별 원본 복구는 강도 0을 명시하고 전체 기본값 상속과 구분합니다.
- **인물 프리셋:** 얼굴 밝기·그림자·색 균형·하이라이트 보호와 선택적 피부 보정을 하나의 설정으로 구성합니다. 원본 기반 미리보기/출력에 같은 설정을 적용하고 얼굴이 없는 사진의 대안을 명시합니다.
- **카메라 서비스:** 예정된 Features/Camera 및 Services의 촬영 서비스가 세션·권한·활성 장치·포맷·줌 범위·사진 출력을 담당합니다. 세션 작업은 UI를 막지 않도록 격리하고 SwiftUI 화면에는 상태와 동작만 제공합니다. 기존 시스템 피커는 전환 완료까지 유지합니다.
- **배율:** 장치 실제 줌 값과 화면 표시 배율을 구분합니다. 활성 구성 변경 시 허용 범위를 갱신하며 핀치·슬라이더·배율 버튼은 동일한 상태와 범위 제한을 공유합니다. 촬영에는 화면 크기 확대가 아닌 장치 줌 설정이 반영되어야 합니다.
- **촬영 입력:** AVCapturePhotoOutput의 사진 데이터를 편집 원본으로 전달하고 중간 UIImage→JPEG 재압축을 피합니다. 회전·전면 미러링·취소·연속 촬영은 명시적으로 처리합니다. 원본 촬영 데이터와 내보내기 해상도 정책을 분리합니다.
- **분석과 상태:** 원본별 얼굴/사람 분석 결과를 재사용하되 메모리 한도와 사진 교체 시 폐기를 둡니다. 분석 중·미검출·실패를 구분하고 미리보기와 출력의 마스크 좌표·효과 반경을 일관되게 변환합니다.

PF-026에서 인물 선택을 렌더링 적용 범위와 분리했습니다. 렌더러는 모든 얼굴의 개별 강도 또는 전체 기본 강도를 적용합니다. 개별 효과 끄기는 0을 명시하며, 모든 인물 강도 변경은 해당 효과의 개별값을 덮어씁니다. 대상 선택만으로는 재렌더링하지 않습니다. 변경 근거는 [DECISIONS](DECISIONS.md)의 PF-026을 참고합니다. 최초 카메라 단계는 필터 없는 촬영 미리보기 후 정지 사진 보정입니다.


## PF-027 · 화사한 인물 프리셋

`PhotoFilter.brightPortrait`를 인물 추천 영역에 제공합니다. 전체 필터 강도 기본값은 기존과 같은 0.5이며, 프리셋 밝기는 0.65(0~1), 따뜻함은 0.15(-1~1)입니다. 프리셋 간 이동은 설정을 보존하고 초기화·사진 교체는 기본값으로 되돌립니다. 피부 질감 보정은 기존 별도 설정을 사용하며 자동으로 켜지지 않습니다.

`BrightPortraitFilter`는 33³ RGB 색상표로 중간 밝기·그림자를 올립니다. 가장 밝은 채널에 따라 증가량을 줄여 흰색과 유색 하이라이트를 보호하고, 따뜻함은 채널 간 균형을 조절하되 가중 밝기를 유지하도록 제한합니다. 형태 변형·기본 흐림·추가 채도 증폭은 없습니다. 전체 화면에는 밝기 설정의 55%를 적용하고, 검출된 모든 얼굴의 부드러운 타원 영역에는 설정 밝기를 적용합니다. 프리셋은 사진 전체의 스타일이며 PF-026의 개별 피부·조명 선택과 독립적입니다.

`PortraitFaceDetecting`은 정규화된 얼굴 사각형만 전달합니다. 기본 구현은 `VNDetectFaceRectanglesRequest`이며 검출 실패 또는 얼굴 없음에는 전체 톤 보정만 남깁니다. 시뮬레이터 테스트에서는 고정 얼굴 영역을 주입해 분석 지원 여부와 무관하게 마스크·다중 인물·출력 일관성을 검사합니다. 이는 실제 얼굴 검출 성공을 증명하지 않습니다. 피부 질감·기존 인물 조명·배경 흐림은 여전히 별도 Vision 경로를 사용합니다.

미리보기와 JPEG 출력은 같은 프리셋을 사용하며 최종 결과를 원본과 강도 비율로 혼합합니다. 프리셋 강도 0은 이 프리셋만 끄며 독립된 피부·조명·배경 효과까지 초기화하지는 않습니다. 전체 초기화와 원본 누름 비교는 기존 동작을 유지합니다. 마스크는 긴 변 512px의 정규화 좌표에서 만들어 출력 크기에 맞춰 확대합니다. 실제 검출 영역의 해상도별 차이와 옆얼굴·가림 경계는 PF-032에서 추가 검증합니다.


## PF-028 · 전용 정지 사진 촬영

기존 `UIImagePickerController`를 `CameraCaptureSheet`의 전용 화면과 `Features/Camera/CameraModel`, `CameraPreview`, `Services/CameraService`로 대체했습니다. `CameraServing` 경계로 실제 AVFoundation 서비스와 테스트 대역을 나눕니다.

- **세션:** 입력·사진 출력 구성, 시작/정지, 장치 잠금, 전후면 전환, 촬영 상태는 전용 직렬 큐에서 처리합니다. 미리보기 연결은 `AVCaptureVideoPreviewLayer`가 담당합니다. 후면 기본 광각으로 시작하고 없으면 전면을 사용합니다. 여러 렌즈와 지원 배율 탐색은 PF-029의 범위입니다.
- **제어:** 전후면 장치가 모두 있을 때 전환합니다. 초점 위치는 preview layer의 좌표 변환을 사용하며 장치가 지원하는 초점·측광만 적용합니다. 노출은 장치 범위와 ±2 EV의 교집합을 사용하고 미지원이면 숨깁니다. 플래시는 사진 출력의 지원 모드만 표시하고 전환 후 미지원 모드는 끕니다.
- **사진 전달:** `AVCapturePhoto.fileDataRepresentation()`이 제공하는 JPEG 데이터를 그대로 편집 모델에 전달합니다. UIImage는 유효성 확인/표시만 수행하며 입력 단계의 추가 JPEG 재압축은 없습니다. 기존 편집 출력에서만 결과 JPEG를 만듭니다.
- **구도:** 현재 앱은 세로 방향을 지원합니다. 미리보기는 `resizeAspect`로 전체 화각을 표시하며 캡처와 미리보기 모두 세로 방향·전면 좌우 비반전으로 맞춥니다. 전면 안내에 저장 정책을 표시합니다. 실제 화각·방향·물리 회전 수용은 실기기 확인이 남았습니다.
- **상태:** 준비/권한 거부/미지원/준비 완료/중단/실패를 구분합니다. 권한 거부는 설정 열기와 재시도를 제공하고 활성 복귀 시 권한을 다시 확인합니다. 비활성·백그라운드·닫기에서는 세션을 정지합니다. 인터럽트 종료 및 media services reset은 활성 화면일 때만 복구하며 다른 런타임 오류는 정지 후 재시도를 제공합니다.
- **촬영 수명:** 모델과 서비스 모두 동시 셔터를 제한하고 전환·노출 조작은 촬영 중 잠급니다. 취소/중단 후 돌아온 데이터를 이전 요청 ID로 걸러 편집기를 덮지 않습니다. 처리/완료 콜백의 촬영 ID가 일치할 때만 데이터를 반환하고 20초 안에 완료되지 않으면 재시도 가능한 오류로 끝냅니다.
- **시뮬레이터:** 기본 실행은 미지원 안내를 표시합니다. Debug의 명시적 `--ui-test-camera` 인자를 사용한 UI 테스트만 합성 색상표를 반환합니다. Release에는 이 대역이 포함되지 않으며 실제 카메라 성공을 흉내 내어 보고하지 않습니다.

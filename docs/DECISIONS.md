# 결정 및 출처

## 기준 자료

사용자가 제공한 [공유 대화](https://chatgpt.com/s/t_6aa0a91ea55c819188ae89927d3681e5)를 2026-09-09 브라우저에서 확인했습니다. 제목은 ‘Nextjs 사진 보정 구현’이지만 공유된 본문은 VS Code와 Xcode를 함께 쓰는 네이티브 iOS 개발 구성안입니다. 공유 페이지에 보이는 답변 범위만 반영했으며 앞선 전체 대화는 확인하지 않았습니다.

## 미정

- 실제 기기 검증 후 지원 버전·성능 목표 재검토.
- 성능 목표와 지원 기기 범위.

공유 답변의 확장·명령어 예시는 설치 환경에 따라 구현 시 공식 문서와 도구 도움말로 다시 확인합니다. Swift/SweetPad 확장은 설치하지 않았으며 프로젝트 생성 도구 XcodeGen만 설치했습니다.

## 문서 정리 이력

2026-09-09 사용자 요청으로 루트의 중복 안내, 과거 초안 사본, 별도 STATUS 문서를 제거했습니다. 환경 이력은 HARNESS_MAP, 진행 상태는 TASKS, 공통 작업 규칙은 WORKFLOW로 통합했습니다.

## PF-003 · 초기 구현 기준 — 2026-09-09

후속 개발을 위한 기본값입니다. 사용자 고정 요구사항이 아니라 이번 구현에서 채택한 변경 가능한 정책입니다.

| 항목 | 초기 기준 |
| --- | --- |
| 플랫폼 | iOS 17 이상, iPhone 세로 화면, SwiftUI |
| 이름 | PictureFilterApp. 로컬 Bundle ID는 com.local.PictureFilterApp; 배포 전 고유 ID 재검토 |
| 필터 | 원본·흑백·세피아·따뜻함·차가움 |
| 강도 | 0~1, 기본 0.5. 원본과 필터 결과를 혼합; 0은 원본, 1은 전체 효과. 원본 필터에는 강도 적용 안 함 |
| 원본 비교 | 비교 컨트롤을 누르는 동안 원본 표시; 설정은 유지 |
| 초기화 | 원본 필터·강도 기본값으로 복귀, 사진 교체도 동일 |
| 출력 | JPEG, 품질 0.9, sRGB, SDR. 투명 입력은 흰색 배경에 합성 |
| 출력 크기 | 방향 보정 후 원본 크기, 긴 변 최대 4096px로 축소; 작은 이미지는 확대하지 않음 |
| 미리보기 | 긴 변 최대 1600px, 출력과 동일 필터 설정 |
| 메타데이터 | 픽셀 방향 정규화, EXIF·GPS 등 원본 메타데이터 복사 안 함. 원본은 유지 |
| 입력 | JPEG·PNG 우선, HEIC 지원 및 HDR 변환 품질은 실제 입력 검증 후 확대 |
| 생성 도구 | XcodeGen으로 project.yml에서 xcodeproj 생성; 외부 앱 런타임 라이브러리 없음 |

필터별 색감 계수는 PF-008에서 샘플 비교 후 기록합니다. 카메라·얼굴 보정은 PF-021에서 오프라인 MVP로 추가합니다. 서버 전송은 범위에 포함하지 않습니다.

## PF-008 · 필터 계산 기준 — 2026-09-14

Core Image를 사용합니다. 흑백은 CIColorControls의 saturation=0, 세피아는 CISepiaTone의 intensity=1로 전체 효과를 만듭니다. 따뜻함은 CIColorMatrix R×1.08/B×0.94, 차가움은 R×0.94/B×1.08이며 G와 알파는 유지합니다. 강도는 CIDissolveTransition으로 원본에서 전체 효과까지 0~1 혼합합니다.

입력은 ImageIO로 방향을 정규화하고 긴 변 1600px 이하 미리보기로 읽습니다. 계산·출력 색 공간은 sRGB이며 미리보기 전송은 PNG입니다. JPEG 결과 저장 정책은 PF-011에서 적용합니다. 현재 색상표 픽셀 검증 기준이며 자연 사진 색감 튜닝은 이후 검토 대상입니다.

## PF-011 · 출력 및 저장 기준 — 2026-09-26

초기 정책인 JPEG, 품질 0.9, sRGB, SDR, 긴 변 최대 4096px, 투명 입력 흰색 합성, EXIF·GPS 등 메타데이터 제외를 적용했습니다. 출력은 저장 시점의 편집 설정으로 원본에서 다시 렌더링합니다. 시스템 사진 보관함은 add-only 권한으로 저장하고, 파일은 시스템 파일 내보내기·가져오기로 처리합니다. 시뮬레이터 권한 거부와 전체 파일 선택 왕복은 후속 확인 대상입니다.

## PF-020 · 카메라·얼굴 보정 범위 — 2026-09-26

촬영 후 편집기에서 보정하는 흐름을 채택했습니다. 실시간 카메라 프리뷰 필터는 첫 구현에서 제외하고, 촬영 이미지를 기존 정지 이미지 경로에 넣어 색상 필터·피부 보정·저장을 함께 적용합니다. 피부 보정은 기본 0(꺼짐)이며 Vision 얼굴 랜드마크 기반 얼굴 마스크 안에서 Gaussian blur를 혼합합니다. 눈과 입 마스크를 제외하고 얼굴을 찾지 못하면 입력 픽셀을 보존합니다. 자동 보정은 기기에서 실행하고 사진을 서버로 보내지 않습니다. 실제 아이폰에서 인식 품질, 결과 자연스러움, 카메라 권한과 캡처 품질을 검증해야 합니다(PF-018~PF-019).

## PF-022 · 사진 스타일·인물 보정 방향 — 2026-09-26

공식 제품 자료에서 Lightroom의 필름풍 프리셋, 사람별 얼굴 부위 마스크와 강도·복원 조절을, Apple Photos와 Google Photos의 촬영 후 인물 조명·배경 흐림을 조사했습니다. 이를 바탕으로 이 앱은 단순 색온도 변형을 넘는 스타일과, 자연스러움·원본 복귀가 가능한 인물 보정을 제공하는 방향을 채택합니다.

- 첫 스타일: **소프트 필름**(부드러운 대비와 따뜻한 톤), **골든아워**(따뜻한 빛과 밝은 하이라이트), **시네마틱**(차가운 그림자와 강조된 명암), **비비드**(선명한 색과 대비).
- 각 스타일은 독립된 이름과 복수의 이미지 조정으로 구별하고, 기존 강도 슬라이더와 원본 비교를 그대로 사용합니다.
- 인물 보정은 사용자가 보정 대상을 선택하고 강도를 조절할 수 있게 하며, 피부 외 영역과 눈·입을 보호하고 원본으로 복구할 수 있게 합니다.
- 얼굴형 변경, 강제 미백, 생성형 변경, 사진 서버 전송은 제외합니다. 인물 조명과 배경 흐림은 현 범위에 넣지 않고 추후 필요를 확인합니다.
- 구현 순서: 스타일 프리셋(PF-023) 다음 인물별 선택형 자연 보정(PF-024). 오프라인 처리와 실패 시 원본 보존을 유지합니다.

참고한 공개 자료: [Adobe Lightroom 프리셋](https://helpx.adobe.com/lightroom/desktop/edit-photos/presets.html), [Adobe 인물 마스킹](https://helpx.adobe.com/uk/lightroom/web/edit-photos/apply-masks/mask-with-ai.html), [Apple 인물 사진 조명·심도](https://support.apple.com/guide/iphone/take-portraits-iphd7d3a91a2/27/ios/27), [Google Photos 인물 조명·흐림](https://blog.google/products-and-platforms/products/photos/google-ai-photo-editing-features-tips/).


## PF-017에서 결정할 항목 — 2026-09-26

- 실기기 서명에 사용할 Apple Developer Team (개인 테스트면 등록된 Personal Team이 선택지).
- 해당 팀에서 사용할 고유 Bundle Identifier. 현재 `com.local.PictureFilterApp`은 로컬 기본값이며 최종 서명 식별자로 확인되지 않았습니다.

이 두 값은 Xcode Signing & Capabilities에서 선택·설정한 뒤 서명 빌드로 검증합니다. Team을 선택하기 전에는 기기에 앱을 설치하거나 실행할 수 없습니다.

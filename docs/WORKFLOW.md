# 문서 및 작업 관리 규칙

문서 진입점은 루트 README.md입니다. 작업 시작 시 해당 문서와 열린 작업 목록(TASKS.md)을 읽고 관련 설계 문서를 확인합니다. 과거 완료 내역을 검토할 때는 TASKS_ARCHIVE.md를 참고합니다.

## 문서별 책임

- MASTER_PLAN: 제품 범위와 화면 흐름.
- ARCHITECTURE: 코드 책임과 데이터 흐름.
- PROJECT_MAP: 현재 및 예정 파일 배치.
- DECISIONS: 선택 근거와 미정 사항.
- HARNESS_MAP: 개발 도구, 환경 확인 이력, 자동화 방식.
- E2E: 검증 시나리오와 실행 증거.
- PORTRAIT_VALIDATION: PF-035 실제 사진 검증의 실행 단위·판정 기준·기록 양식. 상위 업무 상태는 TASKS만 관리합니다.
- TASKS: 열린 작업의 상태, 의존성, 완료 조건, 다음 할 일.
- TASKS_ARCHIVE: 완료·취소된 작업의 상세와 진행 이력.

작업 목록은 TASKS.md 하나만 유지하며 완료·취소 항목은 TASKS_ARCHIVE.md로 옮깁니다. 같은 작업을 두 문서에 중복 기록하지 않습니다. 다른 문서에서 열린 항목은 `TASKS.md#pf-018`, 보관 항목은 `TASKS_ARCHIVE.md#pf-008` 형식으로 참조합니다.

## 진행 관리

- PF-001 형식의 번호는 생성 후 변경하거나 재사용하지 않습니다. 추가 작업은 다음 번호를 사용합니다.
- 상태는 미착수, 진행 중, 차단, 보류, 완료, 취소로 구분합니다.
- 작업 시작 시 상태·담당·갱신일을 기록하고, 종료 시 완료 조건에 대한 증거를 남깁니다.
- 차단은 선행 작업 외의 예상하지 못한 장애, 보류는 기기 부재나 범위 결정 대기입니다. 사유와 재개 조건을 기록합니다.
- 테스트를 실행하지 않았으면 통과로 기록하지 않습니다. 실제 아이폰 검증과 시뮬레이터 검증을 구분합니다.
- 변경에 따라 해당 설계와 작업 항목만 갱신합니다. 요약 수치 및 상태를 다른 파일에 복제하지 않습니다.
- 개인 사진, 위치 정보, 인증서, 계정 비밀은 저장소나 로그에 포함하지 않습니다.

## 체크박스와 리뷰 지정

각 작업은 고정 PF 번호와 체크박스 하나로 관리합니다. TASKS.md에는 열린 작업만 둡니다. `[ ]`는 열림(미착수·진행 중·차단·보류), `[x]`는 닫힘(완료·취소)입니다. 완료·취소 시 체크박스와 상세 상태를 갱신한 뒤 작업 전체를 TASKS_ARCHIVE.md로 옮깁니다. 취소는 완료와 구분해 사유를 남깁니다. 예: “PF-018 리뷰”, “PF-019 진행”. 보관 항목 재개 시 번호를 바꾸지 않고 TASKS_ARCHIVE.md에서 TASKS.md로 옮겨 체크 해제 및 상태·사유를 갱신합니다.
